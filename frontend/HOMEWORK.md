Задание на выходные. Backend и данные на главной уже работают — теперь учимся
**раскладывать UI на layout + страницы** и переключаться между ними без перезагрузки.

## Шаг 0 — поставь `react-router-dom` (сделай первым делом!)

Сейчас в `frontend/package.json` есть только `react` и `react-dom`.
Для навигации без перезагрузки страницы нужен роутер — поставь его **до** первого
`docker compose up`.

`node_modules` живут **внутри Docker-образа** (папка `src` примонтирована, зависимости — нет).
Пакет ставим на хосте, чтобы обновлённый `package.json` попал в git и в следующий build:

```bash
# из корня репо
cd frontend
npm install react-router-dom
cd ..
```

## Шаг 1 — подними всё через Docker

Из **корня репозитория** (Postgres + API + frontend одной командой).
Образ frontend при сборке сделает `npm install` уже **с** `react-router-dom`:

```bash
docker compose up --build
```

Открой http://localhost:5173 — должна открыться нынешняя главная (корзина + акции).
API и данные тоже уже внутри compose, так что на «Главной» цены должны грузиться.

Исходники `frontend/src` и `frontend/public` примонтированы в контейнер — правки в
`.tsx` / `.css` подхватываются без пересборки образа.
Rebuild нужен только если снова меняешь зависимости в `package.json`.

Картинка для сайдбара уже лежит здесь:

```text
frontend/public/icons/banner.webp
```

В React она доступна по URL `/icons/banner.webp` (папка `public/` отдаётся как корень сайта).

## Зачем это нужно

Сейчас всё живёт в одном `App.tsx`: шапка + контент главной.
В моках слева есть **панель с 6 пунктами меню** — разные «страницы» сайта.
Пока её нет, приложение выглядит как одна длинная страница, а не как продукт с разделами.

После домашки:

1. Слева постоянная панель с баннером и 6 кнопками
2. Сверху (справа от панели) остаётся нынешний header — на **каждой** странице
3. Клик по пункту меню меняет только контент справа внизу
4. URL в браузере тоже меняется (`/`, `/about`, …) — можно обновить страницу и остаться там же

## Что реализовать (чеклист)

### 1. Сделать layout: сайдбар + header + «дырка» под страницу

Идея layout’а (как в моках):

```text
┌──────────┬─────────────────────────────┐
│ Sidebar  │  Header (masthead)          │  ← всегда видны
│          ├─────────────────────────────┤
│  баннер  │  <Outlet /> — контент страницы │  ← меняется
│  6 кнопок│                             │
└──────────┴─────────────────────────────┘
```

Заготовка: `src/layout/AppLayout.tsx`.

- Header — это **существующий** блок `.masthead` из `App.tsx` (логотип, «Whisky Index», выбор года).
  Не выдумывай новый header из мока (Тема / Рубли / Поделиться) — это на потом.
- Вместо текущего контента главной в layout’е должна быть «дырка» `<Outlet />` из `react-router-dom`.

### 2. Левая панель (`Sidebar`)

Заготовка: `src/components/Sidebar.tsx`.

Нужно:

1. Вертикальная колонка слева (ширину выбери сам, ориентир из мока ~240–280px).
2. **6 кнопок/ссылок** (названия как в моке):

| Текст            | Путь (предложение) |

Иконки у пунктов и соцсети внизу мока — **не обязательны** для этой домашки.

### 4. Собрать маршруты в `App.tsx` / `main.tsx`

Типичная схема:

```tsx
// псевдокод — допиши сам
<BrowserRouter>
  <Routes>
    <Route element={<AppLayout />}>
      <Route path="/" element={<HomePage />} />
      <Route path="/cart" element={<CartPage />} />
      {/* …остальные */}
    </Route>
  </Routes>
</BrowserRouter>
```

`BrowserRouter` обычно вешают в `main.tsx` (или в `App.tsx` — главное один раз и снаружи `Routes`).

> Наводящий вопрос: что такое nested route и зачем `element={<AppLayout />}`
> без `path` у родительского `Route`?

### 5. CSS под новый layout

В `index.css` сейчас `#root { max-width: 1240px; margin: 0 auto; … }` —
это центрирует одну колонку. С сайдбаром на всю высоту экрана удобнее:

- убрать/ослабить ограничение ширины у `#root` (или перенести max-width на правую колонку)
- сделать flex/grid: сайдбар фиксированной ширины + контент `flex: 1`
- сайдбар на всю высоту (`min-height: 100vh`) — как в моке

Пиксель-перфект 1-в-1 с моком **не требуется**. Нужна узнаваемая левая колонка + рабочие переходы.

## Как устроен React Router (кратко)

```text
клик по <Link to="/about">
  → роутер меняет URL
  → находит Route path="/about"
  → рендерит AboutPage внутри <Outlet /> layout’а
  → Sidebar и Header не размонтируются (если они в layout)
```

Типичные ошибки новичка:

| Симптом | Причина | Что сделать |
|--------|---------|-------------|
| Белый экран / ошибка `useNavigate() may be…` | нет `BrowserRouter` выше | оберни дерево в `BrowserRouter` |
| Клик по ссылке перезагружает всю страницу | обычный `<a href>` | используй `<Link>` / `<NavLink>` |
| Header пропадает на `/about` | header лежит внутри `HomePage` | вынеси в `AppLayout` |
| Обновил `/about` — 404 | в **dev** (Vite в compose) обычно ок; в production-nginx нужен fallback на `index.html` | если в `docker compose` на `/about` + F5 сломалось — напиши в PR |
| Баннер огромный / обрезан | нет `width: 100%` / object-fit | смотри CSS у `img` в сайдбаре |
| Главная пустая, данных нет | перенёс JSX, забыл `useEffect` / state | сверь с старым `App.tsx` через git |
